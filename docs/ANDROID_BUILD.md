# Building the VoicePad Android APK

`android/` is generated by `npx expo prebuild` and is git-ignored, so these are the settings
the v1.1.0 release (versionCode 4) was built with. Re-apply them after a fresh prebuild.

`android/gradle.properties`:
```
reactNativeArchitectures=armeabi-v7a,arm64-v8a
expo.useLegacyPackaging=true        # compressed native libs (extractNativeLibs=true); needed by picky installers such as Android Go phones
android.targetSdkVersion=35
newArchEnabled=true
hermesEnabled=true
org.gradle.jvmargs=-Xmx1536m -XX:MaxMetaspaceSize=512m
org.gradle.workers.max=1            # low-RAM build machines
```

Release signing (`android/app/build.gradle`) reads these Gradle properties, so no secret lives in the repo:
`VOICEPAD_UPLOAD_STORE_FILE`, `VOICEPAD_UPLOAD_KEY_ALIAS`, `VOICEPAD_UPLOAD_STORE_PASSWORD`, `VOICEPAD_UPLOAD_KEY_PASSWORD`
(pass them as `ORG_GRADLE_PROJECT_*` environment variables). Without them the build falls back to the debug key.

Build: `cd android && ./gradlew assembleRelease --no-daemon --max-workers=1 -PreactNativeArchitectures=armeabi-v7a,arm64-v8a`

Ship a universal APK (armeabi-v7a + arm64-v8a) plus a 32-bit-only one (`-PreactNativeArchitectures=armeabi-v7a`),
both signed v1+v2+v3 (`apksigner verify -v`). Keep the release keystore private and reuse it for every
update, or phones will refuse to install the update over the old app.
